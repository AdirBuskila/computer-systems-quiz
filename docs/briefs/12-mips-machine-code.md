# קידוד פקודות MIPS

> 🔑 **בשורה אחת:** כל פקודה היא מילה של 32 ביטים בשלושה פורמטים (R, I, J). קידוד = למלא שדות מטבלה והמיר להקסה. פענוח = לפרק 32 ביטים לשדות ולקרוא מהטבלה. ב-lui/addi הרחבת הסימן של ה-immediate היא המלכודת מספר 1.

## מה המבחן שואל

- פענוח הקסה לפקודת אסמבלי (`25B-A-Q19`) וקידוד פקודה להקסה (`25B-A-Q17`).
- מה יש באוגר אחרי סדרת פקודות עם `lui`, `addi`, `ori`.
- קידוד `beq`/`bne` עם offset שמחושב מכתובות, וקפיצות `j`.

## טבלת השדות

| פורמט | ביטים 31..26 | 25..21 | 20..16 | 15..11 | 10..6 | 5..0 |
|---|---|---|---|---|---|---|
| R | op = 0 | rs | rt | rd | shamt = 0 | funct |
| I | op | rs | rt | imm / offset (ביטים 15..0) | | |
| J | op | target (26 ביט) | | | | |

opcodes ו-funct מופיעים בדף העזר [[cheat_sheet]]. מספרי אוגרים: t0-t7 הם 8-15, s0-s7 הם 16-23, a0-a3 הם 4-7, v0 ו-v1 הם 2 ו-3, at=1, sp=29, fp=30, ra=31 (בכתיבה עם סימן דולר לפני השם).

## מתכון: קידוד (אסמבלי להקסה)

1. מזהים פורמט ומציבים: opcode (ו-funct ל-R).
2. מחליפים שמות אוגרים במספרים בינאריים של 5 ביטים.
3. סדר השדות בקידוד הוא `rs, rt, rd` ולא סדר הכתיבה באסמבלי. ל-R: `add rd, rs, rt`. ל-I: `addi rt, rs, imm`, `lw rt, imm(rs)`.
4. $imm$ ב-16 ביט במשלים ל-2.
5. מצרפים 32 ביטים וקובצים לארבעות לפי הקסה.

## מתכון: פענוח (הקסה לאסמבלי)

1. הקסה לבינארי, 8 ספרות כפול 4 ביטים.
2. ביטים 31..26: אם $000000$ זה R-type ואז funct קובע. אחרת opcode קובע I/J.
3. מפרקים לשדות לפי הטבלה, ממירים מספרי אוגרים לשמות.
4. imm נקרא כמספר עם סימן.

## מתכון: offset של הסתעפות

$$imm = \dfrac{\text{target} - (PC+4)}{4}$$

1. מחסרים את כתובת הפקודה בתוספת 4 מכתובת היעד.
2. מחלקים ב-4 (מספר מילים).
3. כותבים ב-16 ביט (שלילי: משלים ל-2).

## מתכון: קפיצת j

שדה target הוא ביטים $[27:2]$ של כתובת היעד: מחלקים ב-4. הביטים העליונים נלקחים מ-$PC+4$.

## מתכון: lui/addi/ori

- `lui rt, imm`: $rt = imm \ll 16$ (16 ביטים נמוכים אפס).
- `ori rt, rs, imm`: $imm$ מורחב באפסים (zero-extend).
- `addi rt, rs, imm`: $imm$ מורחב **בסימן** ל-32 ביט.
- טעינת קבוע 32 ביט: `lui` לחצי העליון ואז `ori` לתחתון.
- אם משתמשים ב-`addi` לחצי התחתון, ביט 15 הדולק נותן הרחבה לשלילי, ולכן צריך להגדיל ב-1 את החצי העליון.

## דוגמאות

**R:** פקודה `add` עם יעד t0 ומקורות s1, s2: rs=17, rt=18, rd=8, funct=32.

`000000 10001 10010 01000 00000 100000` = `0x02324020`.

**I (פענוח):** `0x8D090004` = `100011 01000 01001 0000000000000100` = `lw` עם rt=9 (t1), rs=8 (t0), offset 4.

**הסתעפות:** `beq` בין t0 ל-t1, בכתובת `0x00400020`, ו-L ב-`0x00400040`. $imm=(0x40-0x24)/4=7$. הקידוד: `000100 01000 01001 0000000000000111` = `0x11090007`.

**רצף:**
```asm
lui  $2, 0x1234
addi $2, $2, 0x8000
```
הקבוע `0x8000` מורחב בסימן ל-`0xFFFF8000`. התוצאה: `0x12340000 + 0xFFFF8000 = 0x12338000`.

## טעינת קבועים וכתובת איבר במערך

- `addi r,zero,0xFFFF` נותן את $c$ מורחב בסימן, כלומר $-1$ ולא 65,535.
- `ori r,zero,0xFFFF` מרחיב באפסים ונותן 65,535 בדיוק.
- שאלת "איזה קטע לא מכניס את הערך" נפתרת בחישוב כל קטע בהקסה, צעד אחרי צעד, כולל הרחבת הסימן של כל `addi`.
- **אינדקס קבוע במערך.** `sw fp, array[4]` כשהכתובת של `array` באוגר t6 היא `sw fp, 16(t6)`: ה-offset הוא האינדקס כפול 4 (מערך מילים) והבסיס הוא האוגר.

## מלכודות

> 🪤 **addi עם immediate שביט 15 שלו דולק.** הפקודה `addi` על אוגר 0 עם immediate `0xAAAA` נותנת `0xFFFFAAAA`, ולא `0x0000AAAA`.

> 🪤 **offset יחסי ל-PC+4.** לא ל-PC ולא בבתים. מחשבים $(target-PC-4)/4$.

> ⚠️ **סדר שדות.** באסמבלי של R הכתיבה היא `rd` ראשון, בקידוד `rs` ראשון.

> ⚠️ **ספרת הקסה אחת היא 4 ביטים.** בשגיאת קיבוץ כל השדות זזים.

> ⚠️ **שדה ה-imm מוגבל ל-16 ביט.** ערך גדול ממנו צריך `lui`.
